# jsDelivr 読込試験

確かめること：
1. 学校の Chromebook（児童アカウント）で、GAS の画面から jsDelivr のプログラムを読み込めるか
2. 児童のメールアドレスを取得できるか
3. jsDelivr から読み込む方式と GAS に直接書く方式で、開くまでの時間に差があるか

## 準備（校務PC・教師アカウント、約10分）
1. 新しいスプレッドシートを作り、「拡張機能 → Apps Script」を開く
2. 次の3ファイルを作って貼る
   - `コード.gs` ← `Code.gs` の中身
   - HTML ファイル `Shell` ← `Shell.html` の中身
   - HTML ファイル `Inline` ← `Inline.html` の中身（約140KB。本番アプリと同程度の大きさにしてある）
3. 「デプロイ → 新しいデプロイ → ウェブアプリ」
   - 次のユーザーとして実行：**自分**
   - アクセスできるユーザー：**ドメイン内の全員**（選択肢の表示名を記録しておく）
4. 出た URL（…/exec）を控える

## 計測（児童アカウントの Chromebook。4GB+LTE機と8GB機の両方）
1. URL を開く（最初は jsDelivr 方式）。表示された結果の○×を確認する
2. 「もう一度はかる（jsDelivr）」を3回、「もう一度はかる（GAS直接）」を3回押す
3. スプレッドシートの「結果」シートに1回ずつ記録される

## 判定
| 結果 | 意味 |
|---|---|
| 「jsDelivr から読み込めませんでした」 | フィルタで遮断されている。この方式は使えない |
| アカウントが「取得できず」 | 児童と教師が別のドメインとして扱われている可能性。公開範囲の設計を見直す |
| 「ボタン→動作開始」の差が0.5秒未満 | 体感で区別できない。jsDelivr 方式を採用してよい |
| 2回目以降の jsDelivr 取得が「端末の保存分」 | 端末の保存が効いている（「通信 0KB」と出る場合は保存の有無を判定できていない） |
