# jsDelivr 読込試験

## 何を確かめるか

| # | 問い | 通らなかった時の意味 |
|---|---|---|
| ① | 児童の Chromebook で、GAS の画面から jsDelivr のプログラムを読み込めるか | 画面を jsDelivr から配る方式は使えない（今どおり GAS に貼る） |
| ② | 児童のアカウントを判定できるか | 名簿と突き合わせる設計がすべて成り立たない（既存アプリでは取れているので、通る見込みが高い） |
| ③ | jsDelivr 方式は、GAS に直接書く方式より遅くないか | 差が 0.5 秒以上なら、速さの面で採用を見直す |

結果のシートにはメールアドレスを残さない（ドメインだけ）。シートはそのまま共有してよい。

## 用意するもの（約30分）

- 校務 PC（教師アカウント）
- 児童用 Chromebook 2台：**4GB+LTE 機** と **8GB 機**（両方で測る。遅さが出るのは 4GB+LTE 機の方）
- 児童アカウント（試験用の児童アカウントがあればそれを使う）

## 手順

### 1. jsDelivr を直接開けるか（校務 PC と児童 Chromebook の両方、各1分）

ブラウザのアドレス欄に次を入れて開く。

```
https://cdn.jsdelivr.net/gh/sankisuguya-create/arithmetic-timeattack@eb3bb39a1f955306e419dd9c53ec452b19dbf3b7/cdn-test/test.js
```

- 英数字がびっしり並んだ画面が出る → 通る
- 「ブロックされました」などの画面 → フィルタで止まっている。**児童の Chromebook で止まったら、ここで試験は終わり**（①が不可）

校務 PC と児童の端末では、フィルタの設定が違うことがある。必ず両方で開く。

### 2. 貼るファイルを手に入れる（校務 PC）

GitHub が開けない場合は、jsDelivr から写す。次の3つを開き、全選択してコピーする。
（`<最新>` は README と同じ版を指す。チャットで伝えたコミット番号に置き換える）

```
https://cdn.jsdelivr.net/gh/sankisuguya-create/arithmetic-timeattack@<最新>/cdn-test/Code.gs
https://cdn.jsdelivr.net/gh/sankisuguya-create/arithmetic-timeattack@<最新>/cdn-test/Shell.html
https://cdn.jsdelivr.net/gh/sankisuguya-create/arithmetic-timeattack@<最新>/cdn-test/Inline.html
```

- jsDelivr は HTML を文字のまま表示する（ページとしては開かない）ので、そのままコピーできる
- `Code.gs` がダウンロードされた場合は、メモ帳で開いてコピーする

### 3. GAS を作る（校務 PC、約10分）

1. Google ドライブで新しいスプレッドシートを作る（名前は「読込試験」など）
2. メニューの「拡張機能 → Apps Script」を開く
3. 3つのファイルを作って貼る

| Apps Script 上の名前 | 作り方 | 中身 |
|---|---|---|
| `コード.gs` | 最初からある | `Code.gs` の中身で**全部置き換える** |
| `Shell` | 「ファイル ＋ → HTML」。名前は `Shell` だけ（`.html` は付けない） | `Shell.html` |
| `Inline` | 同上。名前は `Inline` | `Inline.html`（約34万字。本番の児童画面と同じ文面・大きさにしてある） |

4. 上の保存ボタン（💾）を押す
5. 関数の選択欄で `setup` を選んで「実行」→ 承認の画面が出る
   - 「このアプリは Google で確認されていません」と出たら「詳細 → （プロジェクト名）に移動」→「許可」
   - スプレッドシートに「結果」シートができれば成功

### 4. 公開する（校務 PC、約3分）

1. 右上の「デプロイ → 新しいデプロイ」
2. 歯車 →「ウェブアプリ」
3. 次のように設定して「デプロイ」

| 項目 | 設定 |
|---|---|
| 次のユーザーとして実行 | **自分** |
| アクセスできるユーザー | **（学校のドメイン名）内の全員** |

4. 出てきた URL（`…/exec` で終わる）をコピーして控える
5. 校務 PC でその URL を開き、表に「方式 ○ jsDelivr から読込」「アカウント ○ （教師のメール）」が出ることを確かめる

ファイルを直した時は「デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン：新しいバージョン → デプロイ」。保存だけでは URL に反映されない。

### 5. 児童の Chromebook で測る（1台につき約5分）

1. 児童アカウントでログインし、控えた URL を開く
2. 最初の画面で確かめる
   - 「方式」が ○ か（①）
   - 「アカウント」が ○ で、児童のメールが出るか（②）
3. 画面下のボタンを、**交互に**計6回押す。1回ごとに表示が出そろうのを待つ
   - jsDelivr → GAS直接 → jsDelivr → GAS直接 → jsDelivr → GAS直接
   - 交互にするのは、時間帯による回線の混み方の違いを両方に均等に乗せるため
4. もう1台でも 1〜3 を行う

1回ごとに、スプレッドシートの「結果」シートに1行たまる。

## 結果の読み方

| 列 | 意味 |
|---|---|
| ボタン→動作開始ms | ボタンを押してから、プログラムが動き出すまで。**比べるのはこの列**（GAS の処理待ちも含む、体感に近い値） |
| 画面内準備ms | ページの枠ができてからプログラムが動くまで |
| jsDelivr取得ms | jsDelivr からの取得にかかった時間（jsDelivr 方式だけ） |
| 端末保存分 | TRUE なら、2回目以降は端末に保存した分を使い、通信していない |
| 記録往復ms | `google.script.run` 1往復の時間（両方式で同じになるはず） |
| 端末メモリGB | 4GB 機か 8GB 機かの見分けに使う（ブラウザの仕様で、8GB 機は「8」、4GB 機は「4」と出る） |

| 結果 | 判定 |
|---|---|
| 「jsDelivr から読み込めませんでした」が出る | ①不可。手順1で開けていたなら、GAS の画面の中からだけ止められている |
| 「アカウント」が × | ②不可。デプロイの「アクセスできるユーザー」を確認する |
| 4GB+LTE 機で、jsDelivr 3回と GAS直接 3回の「ボタン→動作開始ms」の平均の差が 500 未満 | ③可。jsDelivr 方式を採用してよい |
| 「端末保存分」が2回目以降も FALSE で「jsDelivr取得ms」が毎回大きい | 端末が保存を残していない。それでも③の差が小さければ採用してよい |

## 困った時

| 症状 | 原因と対処 |
|---|---|
| 「読み込み中…」のまま、10秒後に赤字 | jsDelivr の応答が遅いか、途中で止められている。手順1を児童の端末でもう一度試す |
| 「スクリプト関数が見つかりません：doGet」 | `コード.gs` を貼った後に保存していない、またはデプロイが古い。保存して「新しいバージョン」でデプロイし直す |
| 「ボタン→動作開始」の欄がいつも「もう一度はかる で計測」 | 端末がこの画面の保存領域を使わせない設定。ストップウォッチで、ボタンを押してから表が出るまでを測って代わりにする |
| 「結果の保存 失敗」 | 手順3の5（`setup` の承認）が済んでいない |
| アクセス権が必要です、と出る | 「アクセスできるユーザー」がドメイン内になっていない |

## 終わったら

- 「結果」シートの中身をそのまま伝える（メールは入っていない）
- デプロイは「デプロイを管理 → アーカイブ」で止めてよい。スプレッドシートは消してよい
- このブランチ（`claude/cdn-test`）は、判定が済んだら削除する
