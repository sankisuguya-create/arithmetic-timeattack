# 大きな数TA

万のまとまりから億・兆へ進む位取りの練習。教師が学習の進度に合わせてモードを公開する。

| モード | 出題・回答例 | 範囲 |
|---|---|---|
| 万にわける | 30506 = 3万506 | 10000〜99999 |
| 億・兆にわける | 300040000 = 3億4万、3000400000000 = 3兆4億 | 上位1〜9、下位0〜9999。万未満／億未満は0 |
| 位の数字 | 305060の一万の位 = 0 | 一万〜一兆の位 |
| いくつ分 | 3500000は10000が350こ | 千・一万・一億の1〜9999個分 |
| 10倍・100倍 | 35万×10 = 350万 | 万・億。回答の係数は9999以下 |
| 10分の1・100分の1 | 350万÷10 = 35万 | 万・億。割り切れる整数のみ |

## 設計

- 既存画面の4桁入力上限に合わせ、長い数を回答として丸ごと打たせず、単位ごとの欄または1桁の数字で答える。
- 分解の上位欄は1桁、下位欄は最大4桁。下位の0と途中の0も出題する。既存仕様に従って空欄は0として採点される。
- 確定桁数を `digitCap` で宣言し、短い誤答もEnterで送信できる。共通UIには正答一致時の早期確定・欄移動がある。
- 分解は欄ごとの一致で判定する。例えば3億4万を2億10004万と答えることは認めない。
- 最大の数字表記は9999999999999で、安全に整数として扱える。出題の乱数はCoreから受け取り、保存時の再採点で同じ問題列を再現する。
- 自動解禁の回数条件は設けない。各モードを教師が選べる。読みを声に出す活動、数直線、大小比較はこのUnitには含めない。
- 所要時間は診断の手がかり。読み取りや操作も影響するため、時間だけで理解度を断定しない。

## 検証

リポジトリのルートで `node tests/bignum.test.cjs` を実行する。6万問の独立した計算照合、各型、0と上限、再現性、サーバー採点、共通画面の数字入力経路を確認する。

画面は `tools/preview/preview.html?unit=bignum` で確認できる。

## 設置

[共通の追加手順](../../docs/ADD_UNIT.md#8-設置する)に従い、新しいApps Scriptへ `Unit.gs` と共通のCore・児童画面・教師画面を配置する。setup実行、名簿登録、デプロイ後、教師画面でモードを公開し、ハブにそのURLを登録する。GitHubへのマージだけではApps Script側には反映されない。
