# 大きな数TA

万のまとまりから億へ進む位取りの練習。教師が学習の進度に合わせてモードを公開する。

| モード | 出題・回答例 | 範囲 |
|---|---|---|
| 万にわける | 34560789 = 3456万789 | 万の位1〜9999、下位0〜9999（5〜8桁） |
| 億にわける | 300040000 = 3億4万 | 億の位1〜9、万の位0〜9999（9桁）。万未満は0 |
| 位の数字 | 41087785の千万の位 = 4 | 一万〜一億の位。数の桁数は問う位と独立 |
| いくつ分 | 3500000は1万が350こ | 千・一万は1〜9999こ、一億は1〜9こ |
| 10倍・100倍 | 35万×10 = 350万 | 万・億。回答の係数は9999以下 |
| 10分の1・100分の1 | 350万÷10 = 35万 | 万・億。割り切れる整数のみ |

## 読みの上限

**数字で書き下す出題は9桁（一億の位）まで。** 10桁を超えると、4桁ごとに区切っても
児童が位を数えきれず、測っているものが位取りの理解ではなく「桁を数える根気」に変わる。
兆はこの単元では扱わない。単位つきの表記（`999億` など）は4桁以内なのでこの上限とは別で、
10倍・10分の1は億まで出る。

上限の副作用として、**一億の位（`digitOku`）は答えに0が出ない。**
一億の位が0になる数（10億500万など）は10桁を要するため。0の読み取りは
万のまとまりの位（`digitMan`）で見る。教師画面の tips にも同じことが出る。

## 設計

- 既存画面の4桁入力上限に合わせ、長い数を回答として丸ごと打たせず、単位ごとの欄または1桁の数字で答える。
- 5桁以上の数は共通画面が4桁ごとにわずかな隙間を空けて描く（`ui.html` の `numTok`）。
  区切り記号は入れない。児童がノートに書き写すとき、記号まで写してしまうため。
  3桁のカンマを使わないのは、万進法の区切りが4桁で、3桁区切りが4年の学習内容ではないから。
- 分解の下位欄は最大4桁。下位の0と途中の0も出題する。既存仕様に従って空欄は0として採点される。
- **「位の数字」の数の桁数は、問う位と独立に引く。** 連動させると答えが常に数の
  左から同じ位置に来て、位取りを読まずに「左から○番目」を取るだけで全問正解できる。
  テストが左からの位置の散らばりを検査している。
- 確定桁数を `digitCap` で宣言し、短い誤答もEnterで送信できる。共通UIには正答一致時の早期確定・欄移動がある。
- 分解は欄ごとの一致で判定する。例えば3億4万を2億10004万と答えることは認めない。
- 最大の数字表記は999999999で、安全に整数として扱える。出題の乱数はCoreから受け取り、保存時の再採点で同じ問題列を再現する。
- 自動解禁の回数条件は設けない。各モードを教師が選べる。読みを声に出す活動、数直線、大小比較はこのUnitには含めない。
- 所要時間は診断の手がかり。読み取りや操作も影響するため、時間だけで理解度を断定しない。

## いま入れていないもの

- **位を埋める0を「打つ」練習。** `30506 → 3万506` で下位欄に打つのは `506` なので、
  0の必要は読む側にしかない。逆向き（`3万506 → □`）は答えが5桁で1欄4桁に収まらず、
  モード枠も6で埋まっているため、現行の枠組みでは足せない。
- **10倍・10分の1で単位をまたぐ問題**（`5000万×10 = 5億`）。1欄4桁の制約から、
  答えの単位を問題文と変える必要があり、児童の負荷が上がる。採否は未決。
- **10倍・10分の1の誤答表示の単位。** 型（`times10` など）が万と億を区別しないため、
  `fieldsByType` では単位を付けられない。mistakes シートには素の値が並ぶ。

## 検証

リポジトリのルートで `node tests/bignum.test.cjs` を実行する。6万問の独立した計算照合、
各型、0と上限、9桁の上限、問う位の散らばり、再現性、サーバー採点、共通画面の数字入力経路と
4桁区切りを確認する。

画面は `tools/preview/preview.html?unit=bignum` で確認できる。

## 設置

[共通の追加手順](../../docs/ADD_UNIT.md#8-設置する)に従い、新しいApps Scriptへ `Unit.gs` と共通のCore・児童画面・教師画面を配置する。setup実行、名簿登録、デプロイ後、教師画面でモードを公開し、ハブにそのURLを登録する。GitHubへのマージだけではApps Script側には反映されない。

**`common/ui.html` も更新すること。** 4桁区切りと式のフォント設定は共通画面側にあるため、
`Unit.gs` だけ貼り替えても数字は区切られない。
