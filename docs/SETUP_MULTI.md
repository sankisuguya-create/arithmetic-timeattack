# 全単元を1つの GAS にまとめる（移行の手順）

今までの設置（単元ごとにスプレッドシート＋GAS）を、**1つの GAS で全単元を動かす形**に移す。
記録は今までの単元のスプレッドシートにそのまま書き続ける（移し替えない）。古い GAS には触れないので、いつでも戻せる。

設計：`-` リポジトリ `principles/learning-app-foundation.md`。

## 変わること・変わらないこと

| | 今まで | まとめた後 |
|---|---|---|
| GAS | 単元ごとに1つ | 1つ（＋ハブ） |
| 児童が開く URL | 単元ごとに別 | `…/exec?unit=kuku` のように末尾だけ違う |
| 記録 | 単元のスプレッドシート | **同じ**（登録して使い続ける） |
| 名簿 | 単元ごとに IMPORTRANGE | ハブの roster を直接読む（Base.gs） |
| 単元を足す | スプレッドシートを作り5ファイル貼る | AllUnits.gs を貼り直す（スプレッドシートは最初に開いた時に自動で作る） |
| 教師が見られる学級 | 教師ドメインの人は全学級 | 同じ |

## 手順（校務PC、約30分）

貼るファイルは GitHub の `dist/multi/` にある6つ。**6つとも同じコミットから貼る。**

### 1. まとめた GAS を作る

1. Google ドライブで新しいスプレッドシートを作る（名前は「算数TA（全単元）」など。記録はここには入らない）
2. 「拡張機能 → Apps Script」を開く
3. 最初からある `コード.gs` を消し、次の6ファイルを作って貼る

| Apps Script 上の名前 | 種類 | 中身 |
|---|---|---|
| `Base` | スクリプト | `dist/multi/Base.gs` |
| `Core` | スクリプト | `dist/multi/Core.gs` |
| `AllUnits` | スクリプト | `dist/multi/AllUnits.gs` |
| `index` | HTML | `dist/multi/index.html` |
| `teacher` | HTML | `dist/multi/teacher.html` |
| `coop_shared` | HTML | `dist/multi/coop_shared.html` |

### 2. ハブを設定する

1. 左の歯車「プロジェクトの設定」→ 一番下「スクリプト プロパティ」→「スクリプト プロパティを追加」
2. プロパティ `HUB_ID`、値にハブのスプレッドシートの ID（URL の `/d/` と `/edit` の間）を入れて保存

### 3. 今までの単元のスプレッドシートを登録する

1. エディタで関数 `importUnitSheetsFromHub` を選んで「実行」（初回は承認の画面が出る）
2. 画面下の「実行ログ」に単元ごとの結果が出る（スプレッドシートには何も書かれない。登録はスクリプト プロパティに入る）
   - `○` 登録できた
   - `× links の sheet 列が空` → ハブの links の sheet 列にその単元のスプレッドシートの URL を入れて、もう一度実行
   - `- links に行が無い` → まだ使っていない単元。最初に開いた時に新しいスプレッドシートを作る
3. 関数 `listUnitSheets` を実行して、全単元の登録を確かめる

### 4. 準備して公開する

1. 関数 `setup` を実行（登録した単元のシート・自動実行を確かめる。未登録の単元は飛ばす。結果は実行ログ）
2. 「デプロイ → 新しいデプロイ → ウェブアプリ」。次のユーザーとして実行＝**自分**、アクセス＝**ドメイン内の全員**
3. 出てきた URL（`…/exec`）を控える

### 5. 1単元で確かめる（ここではまだ児童に配らない）

控えた URL の末尾に `?unit=kuku` を付けて開き、次を確かめる。

- [ ] 教師アカウント：児童画面が出る。「せんせい用の ページ」から教師画面が開き、公開モード・集計が今までどおり出る
- [ ] 児童アカウント：本番を1回やり、今までの九九のスプレッドシートの `log` に1行増える
- [ ] 翌朝：今までの九九のスプレッドシートの `daily` / `summary` が更新されている（夜の集計）

### 6. ハブのリンクを切り替える

1. 関数 `switchHubLinks` を実行。ハブの links の url 列が `?unit=<id>` に書き換わる（書き換え前は `links_backup` シートに残る）
2. ハブの児童画面から各単元が開けることを確かめる（反映は最大1分）

**戻す時：** 関数 `restoreHubLinks` を実行すると、url 列が元に戻る。古い GAS は止めていないので、そのまま動く。

### 7. 2週間ほど問題がなければ

古い単元の GAS を「デプロイを管理 → アーカイブ」で止め、その GAS の「トリガー」を消す（夜の集計が二重に走らないように）。
アーカイブしたデプロイは、元に戻せる。

## 単元を足す時（まとめた後）

1. `apps/grade<学年>/<id>/Unit.gs` を書く（`docs/ADD_UNIT.md`）
2. `node tools/bundle/build.cjs` で `dist/multi/AllUnits.gs` を作り直す
3. まとめた GAS の `AllUnits` を貼り直し、「デプロイを管理 → 新しいバージョン」で更新
4. ハブの links に行を足す（url は `…/exec?unit=<id>`）

## しくみ（AI・保守する人向け）

- `UNIT_DEFS` に2単元以上あると、まとめたプロジェクトとして動く（`isMulti_`）。単元が1つのプロジェクトでは今までと同じ
- 画面の `google.script.run.xxx(…)` は、head に埋め込んだ差し替え（`multiShim_`）で `apiCall(<単元>, 'xxx', 引数)` になり、サーバーは呼ぶ前に `UNIT` を差し替える
  - `apiCall` が呼ぶのは、プロジェクトに書いた・名前が `_` で終わらない関数だけ（組み込みの `eval` などは呼ばない）。エディタ用の関数は所有者がエディタから実行した時だけ動く
- 単元のスプレッドシートの ID はスクリプトのプロパティ `unit_sheet:<id>`
- 一時保存・プロパティの名前は `u:<id>:` を頭に付けて単元ごとに分ける（署名の鍵・準備済みの印も単元ごと）
- 夜・朝の処理は `nightlyAggregateAll` などが全単元を回す。4分半を越えたら残りを `continueAll` に回す（GAS の1回6分の上限のため）
- 記録を書く時のロック（`LockService.getScriptLock`）は全単元で共有になる。1件0.1〜0.3秒なので順番待ちは短い見込み（未実測）
