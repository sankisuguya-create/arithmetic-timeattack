# 横断分析の要件定義

単元ごとに閉じている記録を児童単位で束ね、指導と、発達的な困難の見立てに使う機能の要件。
**実装前の文書**で、ここに書いた構成はまだ動いていない。未決の項目は末尾の「未決事項」にまとめる。

## 1. 何を明らかにするか

| # | 目的 | 支える判断 | 状態 |
|---|---|---|---|
| 1a | 学級に必要な指導 | 一斉で何を扱い直すか | 採用 |
| 1b | 児童・小集団に必要な指導 | 誰を取り出すか、誰と組ませるか | 採用 |
| 1c | 有用な指導 | どの手立てが効いたか | 採用 |
| 2 | 学習上の弱さが、どの発達的原因に由来するかの**仮説を立てる材料** | 校内委員会に上げるか、専門機関に何を伝え何を問うか | 採用 |
| 3 | 検出：いま誰を見るべきか | 気づきを待たずに知らせる | 提案（未採否） |
| 4 | 引き継ぎ（次年度担任・中学校） | 個別の指導計画・教育支援計画への転記 | 提案（未採否） |
| 5 | 保護者面談の材料 | 本人の経時変化を示す | 提案（未採否） |
| 6 | 自分の指導・教材の検証 | 手立ての効果を児童・年度をまたいで集計する | 提案（未採否） |
| 7 | 児童への返却 | 自己調整に使う | 保留（可能性は残す） |

**範囲外**：評定（homeroom-tools のノート評価が担う。評定のための記録と支援のための記録は目的が衝突する）、診断。

### 目的1と2に共通して欠けているもの

既存のアプリ（算数TA・漢字の森）が残すのは**結果だけ**で、
「どの手立てを・いつ・誰に打ったか」が残らない。このため、

- 目的1は「必要」までしか言えず、「有用だったか」が言えない
- 目的2は、専門機関が最も必要とする「支援への反応」が出せない
  （DSM-5 の限局性学習症の基準は「困難に的を絞った介入を行っても6か月以上続く」ことを求める）

要件の芯は、データを集めることより、**手立ての記録と結果をつなぐこと**にある。

## 2. 前提と限界

### 測っているもの

- **算数TAが測るのは習熟（知識・技能のうち流暢さ）で、単元テストが測る理解・思考判断表現とは別物。**
  README のとおり、正答率は早期に天井に張り付く。単元テストの得点予測を算数TAで検証することはできない
- **分析の単位は「設問」ではなく「型」。** 出題はシードからの乱数なので、児童ごとに解いた問題が違う
- **1分の制限時間**のため、遅い児童ほど1回の問題数が少なく、型ごとの件数が小さい。判定には最低試行数を置く
- **記録されるのは本番だけ。** 本番の回数の差がそのまま結果に乗る

### 規準（全国の同年齢の分布）が無い

自作アプリのデータで言えるのは「学級・学年の中での位置」まで。「年齢相応か」「障害が疑われるか」は言えない。
WISC などの標準化検査の代わりにはならない。学校の記録が担うのは、検査では見えない部分：

- 日常の場面での困難
- いつから続いているか
- 支援に反応したか
- 領域間の差（例：計算の想起は遅いが漢字は問題ない）

### 目的2の仮説空間

- **候補に発達以外の原因を必ず入れる。** 未習・欠席・前学年の未定着・指導や教材との不一致・算数への不安・
  視力や聴力・睡眠や家庭・日本語の習得度。入れないと、この機能は必ず発達的な仮説を出す。
  文部省（1999）の学習障害の定義と DSM-5 の基準は、どちらもこれらの除外を条件にしている
- **仮説の単位は診断名ではなく「機能」にする。** 観測できるのは課題の成績で、成績から見えるのは機能の強弱。
  語彙の例：数の処理、計算の答えの想起、音韻の処理、視覚と運動の協応、ワーキングメモリ、処理速度、注意の持続、言語理解。
  診断名をシートに残さないことで、ラベル貼りの危険も消える
- **1つの課題の成績では原因を見分けられない。** 「計算の想起が遅い」は数の処理・ワーキングメモリ・処理速度・注意・不安・練習不足のどれでも起きる。
  見分けられるのは、**同じ児童の中で、要求する機能だけが違う課題どうしを比べた乖離**だけ
- **事前確率を添える。** 文科省（2022）の調査で、通常の学級で「学習面で著しい困難を示す」とされた児童生徒は 6.5%（小中、教師回答）。
  30人学級なら約2人

### 平均への回帰

下位の児童は偶然でも上がりやすく、練習すれば誰でも伸びる分もある。
手立ての効果は単独の前後比較で判定せず、**同じ期間の学級全体の変化と比べる**。

## 3. 要件

### 機能

| # | 要件 | 内容 |
|---|---|---|
| R1 | 仮説空間 | 機能の語彙と、発達以外の要因をあわせて定義する |
| R2 | 判別表 | 仮説 × 観測パターンで「支持する／反証する」予測を並べ、根拠文献を付ける。児童の情報を含まないので学校の外で作ってよい |
| R3 | 判別課題 | 4節で「取れない」乖離を埋める課題を足す |
| R4 | 除外要因のチェック | 視力・聴力（健診）、出欠、日本語、前学年の定着、睡眠・家庭。多くは担任が1回入力する。**未確認は「未確認」と表示し、空欄にしない** |
| R5 | 持続性と支援への反応 | 困難が続いている期間と、手立ての記録（対象・開始日・内容・頻度・狙う型や字）。結果は各アプリから自動で取る |
| R6 | 出力を2種類に分ける | ①教師だけが見る仮説シート：仮説ごとの支持・反証の証拠、未確認の項目、**次に取るべき観測**。②校内委員会・専門機関向けの事実記録：仮説を含めず、観測・期間・手立てと反応だけ |

- ①で最も価値が高いのは「次に取るべき観測」。仮説を並べるだけでは行動が変わらない
- ②から仮説を外すのは、専門家の見立てを教師の推測で先に縛らないため
- 行動観察を扱う場合は、日付・場面・行動・頻度・直前の状況・対応・結果を埋める構造化記録に限り、
  校内で検討している児童だけを対象にする（全員分の自由記述は入力が続かず、漏れた時の損害が大きい）

### 手立ての記録の入力コスト

週1回以下、1件10秒前後を目標にする（目安。根拠なし）。

### 個人情報

- 置き場は学校の Google Workspace だけ。Notion・AI・GitHub に児童の記録を出さない
- 学校の外へ出すのは、名前も番号も含まない集計テキストだけ
- 30人前後の学級では出席番号だけでも担任には実名と同じ。番号への置き換えは外へ出してよい理由にならない
- 外部機関への提供は保護者の同意が前提。公立学校には2023年4月から個人情報保護法が直接適用され、
  障害・診断にかかわる情報は要配慮個人情報にあたる
- 教師は診断しない。出力に診断名・推測を入れない（R6②）

## 4. 判別に使う乖離と、既存データで取れるか

| 比べるもの | 見分けに使う仮説 | 取れるか |
|---|---|---|
| 計算の想起は遅いが、位取り・大小（概念）の型は正確 | 答えの想起の問題 ／ 概念理解の問題 | 算数TA（型どうし） |
| 想起時間のゆらぎが大きい ／ 一定して遅い | 注意の揺れ ／ 処理速度・手続き | 算数TA（type_stats の二乗和・対数の和） |
| 練習回数を重ねても伸びない ／ 伸びる | 持続的な困難 ／ 練習不足 | 算数TA（summary の回数と log の推移） |
| 漢字が読めるのに書けない ／ 読めない | 書字（視覚と運動・視覚の記憶） ／ 音韻・語彙 | 漢字の森（記録の粒度は未確認） |
| 1回の中で後半に落ちる | 注意の持続・疲れやすさ | **取れない**。log は型ごとの集計で、解いた順を残さない。Core の改修が要る |
| 時間制限ありとなしの差 | 処理速度 ／ 知識の欠如 | **取れない**。むせいげん練習は記録しない |
| 計算はできるが文章題だけ落ちる | 言語理解・読解 | **取れない**。テストの設問別の記録が要る |
| 音読の速さ・正確さ | 音韻の処理 | **取れない** |
| 宿題の提出・正誤の推移 | 家庭での学習機会（除外要因）・持続性 | homework-scan（データの形は未確認） |

- 練習を重ねても計算の答えの想起が遅いままであることは、算数の学習障害の特徴として報告されている（Geary 2004）
- 反応時間が児童の中でばらつくことは、ADHD との関連が繰り返し報告されている（Kofler et al. 2013）。
  ただし不安・疲れ・練習不足でも起きるので、単独では仮説を絞らない

## 5. 構成（ハブに実装する）

### ハブに置く理由と、既存の設計との整合

名簿の正本と教師の入口がハブにあり、新しいデプロイを増やさずに済むため。

ARCHITECTURE.md は「ハブはリンク集に徹する。進捗・履歴を入れない」とし、理由を「入口としての速さ」としている。
この理由は次の形で守る。実装時に同文書のハブの節を「児童の経路に載せない」に改める。

- 児童の経路（`doGet` → links、`boot`）には手を入れない
- 集計は夜間のトリガーで行い、閲覧は別ページ（`?page=analysis`）にする

### 閲覧者

- 分析ページは**スプレッドシートの所有者と、config の `analysts` に並べた人だけ**に開く。
  ハブの `isTeacher_` はドメイン一致なので、`@edu.nishi.or.jp` の全員が URL を知れば開けてしまう。
  リンクの編集には足りるが、単元横断の児童別データには足りない
- さらに担当学級で絞る（漢字の森の「教師」シートと同じ方式）
- ハブのスプレッドシートは所有者だけのもの（共有なし）とする。集計はそこに置く。
  共有することになったら、集計を所有者だけが持つ別のスプレッドシートへ移す
- 同じドメイン一致の判定で、単元側の weak_child も開ける。これは本機能の外の既存の問題として別に扱う

### データの取り方

| 項目 | 方式 | 理由 |
|---|---|---|
| 読み元の登録 | links の行に「記録シートのURL」を1欄足す（単元を足す時に1回） | 登録を1か所にする。`saveLinks` は8列で全体を書き直すので9列目への対応が要る |
| 型の名前 | 単元の Core が `meta` シート（単元id・学年・型名・モード名・`ENGINE_VER`）を書き、ハブが読む。書くのは `setup` と教師画面を開いた時だけ | ハブは別プロジェクトの `UNIT.types` を読めない。型の定義の正本は Unit.gs のまま。**Core の改修と全単元の貼り直しが要る** |
| log の読み方 | 解析をハブに写し、同じ log の行を両方に通して一致を確かめるテストで縛る | 共通ファイルに切り出すと全単元の設置ファイルが4→5になり、貼り忘れの危険が増える |
| 集計の頻度 | 毎晩1時（単元の `nightlyAggregate` 23時の後）に未処理の log 行だけ読み、児童×単元×型×月の表に足し込む | GAS の6分制限と、年に数万行の log（週600行×単元数からの推定）。月単位は、6か月の持続と練習量あたりの伸びを見るため |
| 読み元の種類 | 読み元ごとに「共通の行の形」へ変換する口（アダプタ）を持つ | 漢字の森・homework-scan を後から足しても集計本体を変えない |

共通の行の形（案）：`児童email | 読み元 | 領域 | 単位キー（型・字など） | 月 | 試行数 | 正答数 | 時間の統計`

## 6. 段階

| 段階 | 内容 | 目的 |
|---|---|---|
| 1 | 算数TAの横断集約と分析ページ。学級の型別誤答率・想起時間・よくある誤答、児童の下位の持続と練習あたりの伸び、下位群の重なり（偶然の期待人数と並べる）、Notion 用の集計テキスト | 1a・1b |
| 2 | 手立ての記録と、学級全体と比べた変化 | 1c・2・6 |
| 3 | 判別表（R2）・除外要因（R4）・仮説シートと事実記録（R6）。読み元に漢字の森・homework-scan を足す | 2 |
| 4 | 判別課題（R3）。解いた順の記録・時間制限なしの記録など、Core の改修を伴うもの | 2 |

判別表（R2）は実装より前に作れる。どの乖離が本当に仮説を見分けるかを先に決めれば、段階4で足すべき課題も決まる。

## 7. 未決事項

- 目的3〜7の採否
- 目的2で行動観察まで扱うか
- 音読の記録を新しく取るか
- 仮説を作る処理の置き場。推奨は、判別表を GAS のシート上の規則として持ち、児童の記録を学校の外に出さない形
- 判別課題（段階4）をどこまで足すか
- homework-scan・漢字の森のデータの形
- 最低試行数と「下位」の定義。**データを見る前に決めて記録する**（見てから決めると、どんな結果も仮説に合わせられる）
