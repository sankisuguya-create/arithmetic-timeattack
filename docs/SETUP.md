# 設置手順

アプリ1つにつき、Google スプレッドシートを1つ用意する。
（ハブ / 九九 / 長さ で計3つ）

## 1. まずハブを作る

名簿の正本になるので、ハブから作る。

1. 新しいスプレッドシートを作成（名前は任意）
2. `拡張機能 > Apps Script` を開く
3. 3ファイルを貼る

| Apps Script 上の名前 | 中身 |
|---|---|
| `コード.gs`（既定） | `apps/hub/Code.gs` |
| `index`（HTML） | `apps/hub/index.html` |
| `teacher`（HTML） | `apps/hub/teacher.html` |

HTML は `ファイル > + > HTML` で追加。**拡張子は入力しない**（`index` とだけ）。

4. 関数 `setup` を1回実行して承認する
5. `roster` シートに児童を入力する

| email | 学年 | 組 | 番号 | 氏名 |
|---|---|---|---|---|
| taro@example-school.ed.jp | 3 | 2 | 1 | 山田 太郎 |

学年・組の表記ゆれ（「2」と「2組」の混在）は別クラス扱いになるので統一する。

6. デプロイ（下記）

## 2. 単元アプリを作る

単元ごとに 1〜4 を繰り返す。

1. 新しいスプレッドシートを作成
2. `拡張機能 > Apps Script` に4ファイルを貼る

| Apps Script 上の名前 | 中身 |
|---|---|
| `Core`（.gs） | `common/Core.gs` |
| `Unit`（.gs） | `apps/<単元>/Unit.gs` |
| `index`（HTML） | `common/ui.html` |
| `teacher`（HTML） | `common/teacher.html` |

3. `setup` を1回実行して承認する
4. `roster` シートの A1 に次を入れ、ハブの名簿を参照させる

```
=IMPORTRANGE("ハブのスプレッドシートURL","roster!A:E")
```

初回だけ「アクセスを許可」を押す。以後、学年やクラスの変更は
ハブを直すだけで全アプリに反映される。

5. デプロイ
6. 教師画面（`?page=teacher`）の「クラスごとの もーど」で、**公開するモードにチェックを入れる**

**6 を忘れると児童の画面にモードが1つも出ない。** 初期状態は全モードがオフで、
学年による自動の解禁は無い（`docs/ARCHITECTURE.md`「モードの公開」）。

## 3. デプロイの設定

`デプロイ > 新しいデプロイ > 種類：ウェブアプリ`

- **次のユーザーとして実行：自分**
- **アクセスできるユーザー：(学校のドメイン名) 内の全員**

この組み合わせのときだけ、児童のメールアドレスが取得でき、
かつ児童はスプレッドシートへの権限を持たない（＝成績を書き換えられない）。

- 児童用 URL：末尾が `/exec`
- 教師用 URL：末尾に `?page=teacher` を付ける

## 4. ハブにリンクを登録する

ハブの教師画面（`?page=teacher`）を開き、単元アプリの児童用 URL を追加する。
学年を指定すると、その学年の児童にだけ表示される。

児童にはハブの URL だけを配ればよい。

## 5. 児童への配布

Classroom か Chromebook のブックマークにハブの URL を登録し、
**全画面（□キー）で使わせる**。

## バージョンアップ

1. ファイルを貼り替える
2. 再デプロイ（デプロイを管理 → 編集 → バージョン「新しいバージョン」 → デプロイ）

`setup` の再実行は不要。シートの新設は次に誰かが開いた時点で自動的に行われる。

**モードの公開をフラグ単位からモード単位に変えた版に上げるときは、`class_config` の
設定が一度リセットされる。** 列名が `allow_<フラグ>` から `mode_<番号>` に変わるため、
古い列は読まれない。貼り替えたあと、教師画面でクラスごとに公開するモードを入れ直す。

## 作り直した版に移すとき（同じアプリの写しを新しく作った場合）

**ファイルを貼り替えるのではなく、スプレッドシートごと作り直したときは、
古い入口を必ず閉じる。**

古い写しをゴミ箱に入れても、ウェブアプリの URL は生きたままで、
児童の閲覧履歴とブックマークからは今までどおり開ける。
古い写しと新しい写しは画面が同じなので、児童も教師も見分けられない。

このとき起きること:

- 教師は新しい写しで公開する。児童は履歴から古い写しを開く → 何も変わらない
- 逆に、教師が古い写しで公開し、児童が新しい写しを開く → 児童の画面は空のまま
- どちらの画面にもエラーは出ない。**「公開したのに反映されない」としか見えない**

手順:

1. ハブの教師画面で、リンクの URL を新しい `/exec` に差し替える
2. Chromebook のブックマークを差し替える（配るのはハブの URL だけにしておくと、ここが1か所で済む）
3. **古い写しの Apps Script を、案内だけのページに置き換える。**
   古いプロジェクトのファイルを全部消し、下の1枚だけにして再デプロイする
   （デプロイを管理 → 編集 → 新しいバージョン → デプロイ）

```javascript
/** 旧版の入口。新しいページへ案内するだけ */
var NEW_URL = 'ここに新しい /exec の URL';

function doGet() {
  return HtmlService.createHtmlOutput(
    '<div style="font-family:system-ui,sans-serif;text-align:center;' +
    'padding:3rem 1.2rem;line-height:2.2">' +
    '<p style="font-size:1.3rem;font-weight:800">この ページは ふるく なりました。</p>' +
    '<p><a target="_top" style="font-size:1.2rem;font-weight:800" href="' + NEW_URL + '">' +
    'あたらしい ページを ひらく</a></p></div>'
  ).addMetaTag('viewport', 'width=device-width, initial-scale=1');
}
```

**古い写しを完全に削除するのは、記録を新しい写しへ移し終えてから。**
削除すると `log` と `summary` も消える。

教師画面の見出しには、**いま操作している写しの名前と、児童に配る URL** が出る。
公開しても反映されないときは、まずそこが児童の開いている URL と同じか確かめる。

## 自動で動くもの

| 時刻 | 内容 |
|---|---|
| 毎日 23時台 | `weak_child` / `weak_class` を自動集計 |
| 毎日 1時台 | `daily` シートの前日分を掃除 |

集計は `log` を全走査するので、児童が使わない時間帯に回している。
授業直後にすぐ見たいときだけ、教師画面の「いま集計する」を押す。

## トラブル対応

| 症状 | 対処 |
|---|---|
| 「名簿に登録がありません」 | roster を確認後、教師画面で「設定を保存」を押す（キャッシュが飛ぶ）。または5分待つ |
| 「ログイン情報を取得できません」 | 実行＝自分／アクセス＝ドメイン内 を再確認 |
| 「現在、ファイルを開くことができません」 | スプレッドシートの URL に `?page=teacher` を付けている。`/exec` の URL を使う |
| ハイスコアが更新されない | 次回起動時に自動で送り直される |
| 順位が誰にも出ない | roster の学年・組の表記ゆれを確認 |
| 児童画面が「まだ もんだいが ひらいて いません」 | そのクラスで公開中のモードが0件。教師画面「クラスごとの もーど」でチェックを入れて**保存**（初期状態は全オフ）。保存後、開いたままの端末にも15秒ほどで出る |
| 児童画面が「よみこみ中…」から進まない | 通信が返っていない。ネットワークか `/exec` の URL を確認する（公開モード0件は上の別文言になる）|
| 一部の児童だけ動く／公開が効く児童と効かない児童がいる | **古い写しと新しい写しが混在している。**教師画面の見出しに出る URL と、児童が開いている URL を突き合わせる（上の「作り直した版に移すとき」）|
| 「サーバーが こんでいます」 | 同時実行が上限に達している。時間を置くと自動で取り直す。頻発するならクラスを2つに分けて開始をずらす |
| IMPORTRANGE が空 | 単元側の roster セルで「アクセスを許可」を押す |

## 最初に必ず確認すること

名簿に自分だけを入れて、**担任アカウントで1回通す**。
`Session.getActiveUser().getEmail()` はドメイン設定によって空を返す事例がある。
ここが通らないと設計全体が成立しないので、40人に配る前に確かめる。
