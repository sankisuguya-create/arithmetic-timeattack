# 新しい単元を追加する

書くのは `Unit.gs` 1枚。Core と共通画面はコピーして貼るだけ。

## 1. Unit.gs を書く

`apps/<単元名>/Unit.gs` を作り、`UNIT` を定義する。

```js
var UNIT = {
  id: 'weight',
  title: 'おもさ タイムアタック！',
  teacherTitle: 'おもさ 設定・分析',

  defaults: { slow_ms: 5000 },        // 共通の既定値を上書き（任意）

  units: { kg: '#FFC53D', g: '' },     // 出題に出る単位と表示色（空=既定のグレー）

  flags: [                             // モードの解禁条件（任意）
    { key: 'calc', label: '計算モード', gradeKey: 'calc_min_grade', defaultGrade: 3 }
  ],

  modes: [
    { id: 1, name: 'かんさん', desc: '3kg=□g', flag: null },
    { id: 2, name: 'けいさん', desc: '1kg300g + 500g', flag: 'calc' }
    // 桁数が揃わず自動確定できないモードは help: 'Enter で こたえあわせ' を足す
  ],

  types: { A: 'kg→g', B: 'g→kg g', C: 'たしざん' },   // 分析の列

  digitCap: { A: { g: 4 }, B: { kg: 1, g: 3 } },     // 自動確定の桁数。キーは型かモードid（3章）

  settings: [],                        // 教師が触る設定欄（6章。不要なら省略可）

  tips: 'weak_child の読み方をここに書く（教師画面に出る）',

  gen: function (rand, mode) {
    // 1問返す
  }
};
```

## 2. 1問の形

すべての単元がこの形で問題を表す。

```js
{
  t:   'A',                     // 問題型。types のキーと一致させる
  q:   ['3', 'kg'],             // 出題の表示トークン
  f:   ['g'],                   // 答えの欄と、その単位
  ans: { g: 3000 },             // 正解
  tag: '3kg'                    // 重複回避と分析用の識別子
}
```

- 単位ラベルが要らないなら `f: ['']`、`ans: { '': 56 }`（`units: {}` にする）
- `q` の中で `units` のキーと一致するトークンは単位として描画される
- `q` に `+` `-` `×` `÷` を混ぜると演算子として描画される
- `q` のトークンが5個以上になると「＝」以下が自動で2段目に落ちる
- `ruler: { from, span, at }` を付けるとまきじゃくが描かれる（**長さ専用。目盛りは cm 決め打ち**）
- `dial: { max, step, label, at, unit, big, bigUnit }` を付けるとまるい文字盤（はかり）が描かれる。
  こちらは単位名を決め打ちしていない。`max`＝一周ぶんの値、`step`＝1目もり、
  `label`＝数字を書く間隔、`big`/`bigUnit`＝大きい単位（例 `big:1000, bigUnit:'kg'` なら
  1000 のところに「1kg」と書く）。大きさは教師設定 `dial_size`（画面の高さに対する%）で決まる
- `t` は必ず入れる。クライアントはこれを表示・集計に使い、自前で型を推測しない

使える補助関数（Core が提供）：

| 関数 | 用途 |
|---|---|
| `ri_(rand, lo, hi)` | lo〜hi の整数 |
| `pick_(rand, arr)` | 配列から1つ |

`rand` は必ず引数の `rand` を使う。`Math.random()` を使うと
サーバーの再採点と食い違い、全員のスコアが0になる。

## 3. 桁数を揃える

自動判定（Enter なしで確定）は桁数で動く。
**桁数そのものがヒントになる**ので、揃える責任は Unit 側にある。

揃える手段は2つあり、**まず `digitCap` を書く**。

### 3-1. digitCap で宣言する（推奨）

「答えが取りうる最大桁数」を宣言すると、その桁数で確定する。
キーは**問題型（`t`）でもモードidでもよい**。型を先に探し、無ければモードを見る。

```js
digitCap: {
  1: { '': 2 },        // モードid：そのモードの全型が同じ桁幅ならこれでよい（九九）
  2: { '': 3 },
  A: { kg: 1, g: 3 },  // 問題型：1つのモードに桁幅の違う型が同居するとき
  B: { g: 4 }          // 欄が複数あるなら欄キーごとに書く
}
```

**1つのモードに桁幅の違う型が同居するなら、型キーで書く。** モードキーでは書けない。
例：「かんさん ぜんぶ」には `1200g=□kg□g`（型A：g は下位で3桁）と
`1kg500g=□g`（型B：g は合計で4桁）が同居する。**欄キーはどちらも `g`** なので、
モードキーで `{ g: 3 }` と書けば型Bの4桁目が打てなくなり、`{ g: 4 }` と書けば
型Aが4打目を待って確定しなくなる。型キーならこの衝突は起きない。

型ごとに確定タイミングが変わっても情報漏れにはならない。**型は問題文として画面に出ている。**
漏れるとまずいのは答えの大きさであって、型ではない。

型キーの名前がモードidと衝突しないようにすること（`t: '1'` のような型名を作らない）。

**Core はこの宣言だけを見る。その問題の実際の答え（`ans`）は参照しない。**
ここが要点で、実際の答えの桁数で確定させると、桁数の大小が
「早く確定する／しない」という形でヒントに変わる。さらに、
答えが1桁の問題は1打で確定し2桁の問題は2打かかるため、
**主指標である所要msに、問題の種類ごとの打鍵数の差が混入する**。

九九が実際にこれを踏んでいた。9×9 の積は1〜81 で、1桁の答えが81通り中23通り（28%）。
1桁の答えは1打で確定するので、その段だけ速く見える。
「その段の想起が速い」のではなく「打鍵が1回少ない」だけだった。
`digitCap: { 1: { '': 2 } }` と宣言して全問題の確定タイミングを揃えることで消える。

宣言を省くと従来どおり「正解の桁数 or 欄の上限」で確定する。既存単元との互換のために
残してあるが、**新しい単元では必ず宣言する**こと。

### 3-2. gen 側で値域を絞る

`digitCap` は確定タイミングを揃えるだけで、答えの桁数自体は揃わない。
桁数が揃っていないと、児童が長い誤答を打とうとしても途中で切られる。
`gen` の値域設計でも揃えておく。

| 状況 | 対処 |
|---|---|
| 2欄の下位の桁数がばらつく | 下位を3桁固定にする（例: m部は必ず100〜900） |
| 答えが0になりうる | 0 も出す。「0か否か」が漏れないようにする |
| どうしても揃わない | `modes` に `help: 'Enter で こたえあわせ'` を足して Enter 確定にする |

## 3-3. 型を順番に開ける（任意）

前の型ができないと次が成り立たない単元は、`needs` を書くとモードが順次開放になる。

```js
modes: [
  { id: 1, name: '九九さがし' },
  { id: 2, name: 'あってる？',  needs: { mode: 1, tries: 3, bypass: 'open_all' } },
  { id: 3, name: 'わり算',      needs: { mode: 2, tries: 3, bypass: 'open_all' } }
]
```

- `tries` は**回数**。成績（正答数）にしてはいけない。閾値の適正値が学級ごとに違い、
  下位層が最後のモードに永久に到達しなくなる（`docs/ARCHITECTURE.md`「順次開放」）
- `bypass` は `flags` のキー。教師がクラス単位で一括解除するための逃げ道で、
  既定オフにするなら `defaultGrade: 99` にしておく（どの学年も自動では満たさない）
- 開いていないモードも画面には出る。薄く表示され、開け方の案内が付く
- 回数は本番・練習・制限時間を問わず合算される。ただし記録しない練習（むせいげん）は
  summary に入らないので回数に数えない

## 4. 判定方式を選ぶ

位に分けること自体が目標なら欄ごとの一致（既定）。
値を読むことが目標なら合計での一致。

```js
byTotal: function (item) { return item.t === 'G'; },
scale: { m: 100, cm: 1 }        // 合計判定に使う換算率。関数ではなく宣言
```

合計判定にすると `1m87cm` と `187` の両方が正解になる。

`scale` を関数ではなく宣言にしてあるのは、**同じ値を児童画面にも渡すため**。
以前は `ui.html` 側が `u === 'm' ? 100 : 1` と長さの単位名を決め打ちしていて、
他の単元では合計判定が成立しなかった。

## 5. 誤答を単位つきで表示する（任意）

答えが複数欄にまたがる単元（km/m のような）は、`fieldsByType` を定義すると
weak_class の「よくある誤答」と mistakes シートで単位つきに表示される。

```js
fieldsByType: { A: ['km', 'm'], C: ['m'] }
```

省略すると値をそのまま（スペース区切りで）表示する。答えが単一値の単元（九九など）は不要。

## 6. 教師が調整する設定を足す（任意）

担任が教室で触りたい値（表示の大きさなど）は `settings` で宣言する。
教師画面に入力欄が自動で生まれ、`config` シートに保存され、
児童画面には `boot()` が値を渡す。

```js
defaults: {
  ruler_tape: 128            // 既定値はここに書く
},

settings: [
  { key: 'ruler_tape', label: 'テープの太さ',
    note: 'px。60〜200', min: 60, max: 200, step: 4 }
]
```

- `key` は `defaults` のキーと一致させる。一致しないと既定値が出ない
- 数値以外を入れるなら `type: 'text'` を足す
- 児童画面での読み出しは `uset_('ruler_tape', 128)`。第2引数は保存値が無いときの既定

**Core も `teacher.html` も key の意味を知らない。** 宣言した単元にだけ欄が出る
（長さの巻き尺設定は、九九の教師画面には出ない）。この分離を壊さないこと。

**出題に影響する値をここに置いてはいけない。** 設定は表示のためのもので、
`gen` は `rand` と `mode` しか受け取らない。教師が変えた値で出題が変わる作りにすると、
サーバーの再採点と食い違ってスコアが壊れる。
長さの巻き尺で「表示範囲（span）」を設定項目にしていないのはこの理由で、
span は目盛りの窓と答えの値域の両方を決めているため、表示だけを変えることができない。

## 7. 練習について

練習は2種類ある。どちらも `gen` が出題を作るので、単元側に追加の作業はない。

| 種類 | 経路 | 記録 |
|---|---|---|
| 時間制限あり | `startSession(mode, true)` で200問まとめて受け取る | する（`summary` のみ。`log` とランキングには入れない） |
| むせいげん | `nextPracticeItem(mode, type)` で1問ずつ受け取る | しない |

むせいげんは1問先読みするので、2問目以降に待ち時間は出ない。

### 型を絞った練習

**むせいげんのときだけ、問題型を1つ選んで練習できる。** 単元側の作業は無い。

- 選択肢は `UNIT.types` のラベルを使う。どの型がどのモードに出るかは
  **`gen` を300回回して導出する**（`Core.gs` の `typesInMode_`）。
  `pool` を Unit.gs に別途宣言させると `gen` と二重管理になり、
  片方だけ直したときに選択肢と実際の出題がずれる。出題の正本は `gen` ひとつだけにしてある
- 絞った出題も `gen` から取る（当たるまで引き直す棄却法）。型ごとの生成関数は要らない
- **記録する経路には入れない。** 同じ型ばかりのブロック練習が `log` に入ると、
  weak_child のその型の平均だけが短く出て、診断そのものが壊れる
- **「あなたはこの型が弱い」と画面に出さない。** 児童が自分で選ぶだけにする。
  名指しは、遅さを隠す行動（当てずっぽう連打・欠席）を誘発する（README の weak_child の項）

混合（「ぜんぶ」）の置き換えではなく補助として置いている。
同じ型だけを続けるほうがその場の成績は上がるが、**保持は混合練習のほうが良い**
という所見があるため、既定は「ぜんぶ」のままにしてある。

## 8. 設置する

1. 新しいスプレッドシートを作る
2. `拡張機能 > Apps Script` に4ファイルを貼る

| Apps Script 上の名前 | 中身 |
|---|---|
| `Core`（.gs） | `common/Core.gs` |
| `Unit`（.gs） | 作った `Unit.gs` |
| `index`（HTML） | `common/ui.html` |
| `teacher`（HTML） | `common/teacher.html` |

3. `setup` を1回実行して承認する
4. デプロイ（実行＝自分／アクセス＝ドメイン内）
5. `roster` の A1 に `=IMPORTRANGE("ハブのURL","roster!A:E")`
6. ハブの教師画面でリンクを追加する

## 9. 確認すること

- 名簿に自分だけ入れて、担任アカウントで1回通す
- 教師画面で `weak_child` が意図した列になっているか
- `slow_ms` の既定値は当てずっぽう。1〜2週で分布を見て調整する

## やってはいけないこと

- **Core に単元固有の分岐を書く。** 増えるほど Core が壊れやすくなる
- **クライアントに出題ロジックを持たせる。** サーバーと二重管理になり、
  片方だけ直した瞬間に全員のスコアが0になる。
  `ui.html` の `previewItem()` は GAS の外で画面を見るためのダミーで、
  ここに単元の出題を書いてはいけない
- **`ui.html` / `Core.gs` に単位名や問題型の文字列を直接書く。**
  `units` と `t` を経由させる
- **`log` に問題単位で全部記録する。** 1年で行数が破綻する
